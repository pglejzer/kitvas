# 0055. The editor at every width and state, live checks, waivers, lists and uploads

Date: 2026-11-24. Status: accepted, changed in part by ADR 0065. Spec: `docs/specs/2026-11-24-kitvas-stage-4c-editor-design.md`. Builds on ADRs 0048 to 0054. Makes the Tailwind style edits of ADR 0050 writable, and lifts the `.map` refusal of ADR 0051 for literal arrays.

## Context

Stages 4a to the editor screen let a person change one element at one width in its resting state. A real page lives at three widths and in several states, and a change must not break what it does not show. The aim is an editor that sees and writes the whole element and says at once what a change broke, as Figma, Webflow and Framer do, while the code stays the canvas.

## Decision

- **Width cascade A, mobile-first.** An edit applies from the width it is made at upward, as CSS `min-width` and Tailwind `md:` work. At the base width (the smallest preset, 390) it applies to all widths. The value shown at width W is the nearest block at or below W. Breakpoints come from `kit.json` (`breakpoints`, 1 to 4 integers); without them they are 768 and 1280, the studio's preset widths. A width that is not a kit breakpoint is refused (`not-breakpoint`).
- **Contexts are written as nested blocks and prefixes, never as new files or inline styles.**
  - SCSS: `@media (min-width: Npx) { … }` blocks inside the element's class rule, in ascending order after the base declarations, then `&:hover`, `&:focus-visible` and `&:active` blocks; a state at a width nests inside that width's media block.
  - `setStyle` and `removeStyle` carry an optional `context` and `newBlock` or `dropBlock`, so a write and its inverse give the file back byte for byte; a block left empty goes.
  - Tailwind: a new op `setUtility` adds, removes or swaps one utility in the element's literal `className`, with the screen prefix first and the state after it (`md:hover:p-6`). An expression `className` or an unknown value is refused.
  - An override equal to the value below it is still written. An off-kit value is marked in any context.
- **A property a prop covers is refused at another width or state** (`prop-covered`): kit props have one value for all widths and states (ADR 0050, decision 9). The panel says so and offers Ask Claude.
- **Forced states by twin rules.** The frame copies each stylesheet rule that uses `:hover`, `:focus`, `:focus-visible` or `:active` into a twin that selects the element through `[data-kv-force~="hover"]` (and `focus`, `active`) in a style element of its own, and sets the attribute on the forced elements only. The twins are made again when the stylesheets change. Forcing is a preview: it never reaches the build, a file or Preview mode, and it ends with Edit or with the selection. Rejected: the DevTools protocol's forced pseudo-state, which an ordinary browser tab cannot use, and classes written into the build. The sandbox gives the frame an opaque origin, so reading its own sheets' rules is a cross-origin read: the prototype origin now answers a stylesheet (and only a stylesheet) with `Access-Control-Allow-Origin: *`. This adds to ADR 0022: the random key in every path still keeps other sites from finding the files, and a draft's CSS holds nothing secret.
- **A state the kit styles more specifically is refused, not written** (`kit-state-wins`). The editor writes a state as `.class:hover`, (0, 2, 0). A kit rule for the same state often weighs more (`.kit-button--outline:hover:not(:disabled)`, (0, 3, 0)), and then a written value never shows. While a state is forced, the edit card's frame names the longhands that its twin rules heavier than (0, 2, 0) set on the selected element; their rows say so and a pick offers Ask Claude, as with `prop-covered`. A live check also holds a state edit against the build while that state is forced. Rejected: raising the written selector's weight (`&.button:hover`), which wins at once but leaves a harder-to-read rule in the person's SCSS.
- **One frame per width.** Each card is its own frame of the current version; cards are added and removed, never moved or re-parented, so no frame reloads. Rejected: container queries, because kits use media queries, so a frame narrower than the window is the only true view. The selection is shared; the card last clicked in is the edit card and sets the context's width.
- **Live checks in the frame and on the server, not a browser check per edit.** After a build, every card measures the changed elements: text contrast, target size, content wider than its box, text cut by `overflow: hidden`, and each previewed value against the computed one (`mismatch`). Each applied edit also answers with the code findings of the files it changed (off-kit values, raw values, imports, plain controls), which need no browser. Both answer in milliseconds; they run after a build, debounced, never during a drag. Rejected: a Playwright check per edit (3 to 10 s) and axe-core bundled into every prototype. During a session only the live checks run; Save version starts the full check in the background.
- **Waivers.** A finding of a full or live check can be accepted with a reason of 1 to 300 characters. `<draft>/waivers.json` holds `{rule, element, reason, version, at}`, at most 500. A waiver carries to later versions while its element exists, following the rename log of ADR 0052: the later steps of its own version and every step of the versions after. `kitvas check` lists accepted findings apart (`waived` in `checks.json`, `summary.waived`), and they are not counted as fix or review. The studio shows them as accepted, never as marks.
- **Data lists.** An element inside a `.map` over an inline array or a `const` array of the same file can be moved, duplicated and deleted as an item, and its `{item.field}` text edited when the field is a string literal. Each op rewrites only the touched items' text; commas, line breaks and indentation stay, and the inverse is exact. A list from a prop, an import or a computed array stays read-only with the reason.
- **Image uploads.**
  - `POST /api/v1/drafts/{slug}/images` stores an image in the latest version's `src/img/` under a safe, unique name: lower case, `a-z`, `0-9` and `-`, the type's extension, `-2`, `-3` on a clash.
  - Accepted: PNG, JPEG, WebP, AVIF and GIF, up to 5 MB. The first bytes must match the declared type; SVG and any markup are refused, because they can carry script.
  - The route has its own body limit (`bodyLimit` on a route, never below the studio's).
  - A drop on an `img` or a kit image component sets `src`; a drop on any other element sets the background image, unmarked as in ADR 0054; a drop on the Insert tab only stores the file. Each write is an ordinary edit with undo.

## Consequences

- `ops.ts` gains `setUtility` and the list ops; `StyleContextSchema` is the one shape of a context. Old ops, which have no context, mean the base and behave as before.
- The edit frame bundle gains the force, live and list code; the page and the frames still share only `client/channel/`.
- A forced state, an outline or a live mark never reaches a build, so a draft's files hold only what the person wrote.
- `checks.json` may carry `waived` and `summary.waived`; a reader that does not know them ignores both.
- A waiver follows ids through the rename log only. An element whose id changed in a way the log does not hold (a change by Claude) no longer carries the waiver, and the finding shows again.
- An uploaded file stays in `src/img/` when the edit that used it is undone; an unused file is harmless and goes with the version.
- Not part of this decision: previewing a component variant on hover over a prop option, hide and lock across reloads, AI in the editor, notes and the timeline (4d), and per-width props.
