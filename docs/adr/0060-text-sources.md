# 0060. Text sources

Date: 2026-11-24. Status: accepted. Builds on ADRs 0049 and 0055.

## Context

A double click edits an element's text in place. Until now that worked for a plain JSX text and for the field of a literal list item that the element reaches through elements from the callback's root (`<Heading>{plan.name}</Heading>`). Most texts of a real draft are neither: a button whose text is a list item's field inside `{loading ? … : <>…</>}`, a feature in `plan.features.map(…)` inside `plans.map(…)`, a `{plan.free ? 'free forever' : annual ? plan.billed : 'billed monthly'}`. The double click did nothing there, silently. In the same drafts an element whose `className` is an expression (`{plan.featured ? 'plans__card plans__card--featured' : 'plans__card'}`) took no style at all.

## Decision

- **One rule: the string literal that renders the text the person saw.** Given the element, the text shown and the picked copy's path (its place in each `.map` around the element, outer first), the server finds the one string literal of the same file that produced it. The element's only child must be one `{…}`. Its operands are the branches of `?:`, both sides of `||` and `??`, the right side of `&&`, inside any brackets. An operand that is a string literal (or a template without `${}`) is a candidate when its value is the text shown. An operand that reads a callback's parameter (`plan.action`, `feature`, a field a `({ title }) =>` pattern binds) is a candidate when the item at the path holds a string literal there with that value.
- **Lists from the inside out.** Each `.map` whose callback returns one root element is a level; an element in a condition or a fragment of the callback belongs to the item of the callback's copy it sits in. A level maps over a literal array or a same-file `const` as before, or over a field of an outer item (`plan.features`), which is the array literal in that field of the outer item the path names. A `.map` without one root element per item (a condition at the callback's top, a fragment root, `flatMap`) has no countable copies.
- **Exactly one candidate is written; anything else is refused.** None is `computed`, several are `ambiguous`. An operand whose value the editor cannot read (a call, a variable, a prop, a component, a field that is no string literal) may be the text itself, so it refuses too (`computed`); `null`, `undefined`, a boolean, a page element and a field the item does not have show nothing and are passed over. An operand that reads an item the path cannot name refuses (`computed`, or `list-item-gone` and `not-found` when the list changed). The literal is rewritten in its own quotes and nothing else changes, so the server's hunk inverse gives the file back byte for byte. Never a guess.
- **The op is `setItemText` with an optional `path`.** Without `path` it is exactly the op of ADR 0055, and the cases that worked keep sending it; `findList`, `listInfo` and `itemTexts` keep their meaning. With `path`, `item` is the path's last place, for the change list.
- **Ask before opening.** Inspect gives `expression` for an element whose children are text and `{…}`, no element, and a `{…}` with an operand that is no element, with the ids of the list roots around it. On a double click the page asks the frame (`locate-copy`; the canvas protocol has a `locate` of its own) for the copy's path, counted by the copies of each root inside the copy of the root before it, and for the text it shows; then it asks `GET …/text-source` (read only) whether that text has its literal. Only then the frame opens the editor. A text without one is refused at once, in the panel's refusal place with Ask Claude, with words that say why; never silence. A copy that shows elements (a container around a `.map`) opens nothing: that double click is no text edit.
- **The frame keeps the page true.** The `text` message carries the text the editor started from, which is the op's `before`. A refused or conflicting write sends `text-back`, and the frame puts the old text back. The page is held busy from the start of an inline edit to its end, so it is never swapped under the typing.
- **An expression `className` with a constant first class can take styles.** When every value its operands can give (with `&&`'s left side, as a falsy value gives no class) is a string literal or a template literal with a static start, and all start with the same writable class, that class is the style class (`exists: true`); a style op writes its rule and touches no TSX. Anything else stays read-only. Tailwind drafts still refuse an expression `className`.
- **The add modifier.** Shift, Ctrl and Cmd all add to the selection, in the frame and in Layers; a double click with one held starts no text edit.

## Consequences

Most texts of a generated draft can be typed in place, and the ones that cannot say why and offer Ask Claude. The rule reads only what the file writes, so a text from a prop, an import or a call stays Claude's. Two reads per double click (the frame, then the server) cost a moment before the editor opens; the inspect answer compiles the file once more for an element inside lists, to name the list roots.
