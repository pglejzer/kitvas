# src/drafts

Drafts in a project's workspace: `.kitvas/drafts/<slug>/`, one folder per version (`v1`, `v2`), files split by type (`md/`, `src/tsx/`, `src/scss/`, `src/json/`, `src/img/`).

- `draft.json` follows the zod schema in `domain/draft.ts`. Change the schema, never a hand-written type.
- `md/layout.md` is written by an agent and read by `domain/layout.ts`: `## <section-id>` headings with a `Purpose:` and a `Components:` line. A section id is lower-case words joined by `-`; its component and file name is the PascalCase form (`domain/names.ts`). `## shared` is reserved: its text goes to `Layout.shared` and every section context, and it is never a section.
- An optional `Screen: <kind>` line before the first section sets `Layout.screen`: `landing`, `form`, `sign-in`, `sign-up`, `checkout`, `dashboard`, `list`, `detail`, `article`, `settings`, `other`. An unknown kind is the issue `unknownScreen`. Some checks run only for a kind.
- `src/tsx/index.tsx` and `src/scss/index.scss` are generated from the layout (`domain/entry.ts`). Never edit them by hand; `kitvas layout <slug>` rewrites them.
- A problem in a draft is an `Issue` with a message key (`draftIssue.<name>` in `locales/en.json`). Only a missing draft, a draft.json that fails the schema, or a path outside the draft throws.
- All file access goes through `DraftStore`; paths inside a draft are relative with forward slashes. The store refuses anything outside the draft folder.
- A new version copies `md/`, `src/` and `why/` of the latest one and never `build/`.
- Stage 4d (ADR 0056): `notes.json` and `view.json` sit beside `draft.json`, with ids as the version that wrote them named them; `app/notes.ts` and `app/view.ts` bring them to the latest version through the rename log, as waivers do. `<version>/why/<Section>.json` holds a section's reasons (`domain/why.ts`); `app/why.ts` reads them, `stampWhy` replaces an agent's 64 zeros with the sha256 of the section's TSX, and a hash that no longer matches is `stale`. A file that does not read is left out.
- This module reads kits only through `src/kit/index.ts`.
- The optional `edit` field of `draft.json` (`{ version, startedAt }`, ADR 0049) is the open editing session: open only while `edit.version` is the latest version (`app/edit-session.ts`). Never write it by hand; the editor starts and ends it.
- `DraftStore.replaceAll(slug, files)` writes several files all or none: each to a temporary file, then renames; a failed rename puts the files already renamed back. Use it when one change spans files. A path outside the draft throws `DRAFT_INVALID` before anything is written. A rename that Windows refuses because another process holds the file for a moment (`EPERM`, `EBUSY`, `EACCES`) is tried again for about 1.3 s before it fails (`adapters/rename-retry.ts`).
- `domain/layout-edit.ts` moves, adds and removes whole `## <id>` blocks of `md/layout.md`; the text outside the blocks and the `## shared` block stay as written. A section op also moves its TSX and SCSS files (`replaceAll` with `text: null` removes a file and can put it back).
- `app/rename-log.ts` keeps `edit/renames.json` in a version: the id renames of each edit request (ADR 0052). The build never reads it; a broken file reads as empty.
- Delete (ADR 0064): `app/trash.ts` moves a draft's folder whole to `.kitvas/trash/<slug>~<stamp>/` (`DraftStore.trash`, `adapters/fs-draft-trash.ts`, names in `domain/trash.ts`), brings the newest copy back, or removes copies for good (`purge`, a step of its own). A move that Windows refuses after the retries is `DRAFT_LOCKED` with the draft left where it was; a trash name that does not parse is never read or removed.
- Options (plan 25, ADR 0082): `src/json/options.json` holds the choices of a version, read only by `readOptions` (`app/options.ts`; checks and hand-off call it too), checked by `checkOptions` (the option `theme` needs the kit's theme ids), their default changed in place by `setOptionDefaults`. `kitvas layout` writes `src/tsx/options.ts` and an entry that passes `options` to every section only when the version has options, and removes a stale `options.ts`. Craft drafts and a rework's `before/` have none.
- Kinds (ADR 0045): `kind` is `screen`, `rework` or `craft`, and each carries only its own block. A craft draft's sketches are `src/tsx/sketches/A.tsx`, `B.tsx`, `C.tsx`; its entry is generated (`domain/craft-entry.ts`), and the next version after a pick holds only the picked sketch. A craft draft's `md/brief.md` has the headings of its subject (`craftBriefTemplate`), not a screen's. It has no section context: `app/craft-context.ts` is its own (`kitvas context <slug>` without `--section`, saved as `build/context/craft.json`).
