# src/edit

The editor's write-back (stage 4a): operations from the studio's panels applied to a draft's TSX and SCSS by kitvas itself, without an AI. Spec: `docs/specs/2026-11-23-kitvas-stage-4a-editor-core-design.md`.

- `domain/` is pure: text in, text out, no I/O. An apply function returns the new text and the changed spans, or a refusal (`domain/types.ts`), never a part of a change.
- An edit touches only its own span. Never reformat, re-indent or re-quote anything else; keep the file's line endings (CRLF stays CRLF) and its indentation.
- Every operation has an exact inverse (`domain/ops.ts`). Applying an operation and then its inverse gives the file back byte for byte; the round-trip tests hold that for every fixture file.
- The JSX reader skips strings, template literals, comments and JSX inside `{…}`: an apostrophe in JSX text never starts a string. It never executes or evaluates draft code.
- An element is found by its id. When the file is the one the build read, `build/json/ids.json` gives the place; otherwise the id is found again in the current text through `EditCompiler.jsxDev` and `readSites`/`elementIds` from the render module, never by the old line.
- A request writes all its files or none: new texts are made and checked in memory first, then written (`DraftStore.replaceAll`).
- Styles are written as `var(--kit-…)`; a raw value gets the off-kit marker after its semicolon. A keyword of the property's list, or an image of the version, is written as it is without the marker (`mark: false`). Never an inline `style` in TSX, never an id attribute in TSX.
- Writes stay inside the draft's own version folder.
- Structural edits (stage 4b, ADRs 0051 and 0052): `domain/structure/subtree.ts` reads spans and children, `domain/structure/apply-structure.ts` and `domain/structure/apply-wrap.ts` splice them, `domain/tsx/format.ts` keeps indent and line endings. Remove then insert at one place restores the file byte for byte.
- In a request, ids name elements as they were before it. `app/structure/structural.ts` (with the request's texts in `app/request-state.ts`) carries each op's effect forward and answers with `renames`, `created` and the server-made `inverse` (`patch` hunks and `file` ops, `domain/structure/patch.ts`). Undo uses that inverse, never a snapshot.
- After a structural change `domain/tsx/kit-imports.ts` makes the `@kit` import match the components used, and touches no other import.
- An element written as an expression's own JSX (what a `.map` callback returns, a branch of a condition), a section root and a slot root never move or get deleted as elements. Only the element's own place counts (ADR 0065): a plain child inside a list item's template moves, duplicates and is deleted like any other, and the change shows in every item. A subtree that names local variables moves only within its function body. Refuse with the reasons in `domain/types.ts`, never guess.
- The structure map (`app/structure/structure.ts`; ADRs 0059 and 0065) says for each element the lists around it (`lists`: the ids of the roots their callbacks return, outer first; `null` when one cannot be counted) and whether it is a list item (`item`): the root its innermost list's callback returns, at any depth, when the array of its first copy is a literal of the file. The frame drags an item's copies to change the data with `moveItem`; an item never moves as an element.
- Style properties (ADR 0054): each property in `STYLE_PROPERTIES` has a value kind, a token type, a `keyword` list or an `image`, beside `PROPERTY_TOKEN_TYPE`. Per-side `padding-*` and `margin-*` are dimensions with tokens first. A keyword from its fixed list is never off-kit; any other keyword is refused (`invalid`). `background-image` is only `url(../img/<file>)` of a file in the version's `src/img`. A kit prop that covers a property still wins. Write then undo gives the file back byte for byte for every property.
- The session (`app/edit-session.ts` in drafts): `reopenEditSession` writes an ended session back only while its version is the latest and no session is open; it never starts a version.
- Contexts (stage 4c, ADR 0055): a style op with a `context` writes a nested `@media (min-width: Npx)` block, a `&:hover`, `&:focus-visible` or `&:active` block, or a state block inside a media block; an op without one is the base. A block an op creates (`newBlock`) is removed by its inverse (`dropBlock`), so write then undo is byte for byte. A width must be a kit breakpoint (`not-breakpoint`); a property a kit prop covers is refused at any other context (`prop-covered`). Tailwind drafts write a `setUtility` with the screen and state prefixes into a literal `className`; an expression `className` is refused.
- Class rules (ADR 0067, `domain/style/scss-rules.ts`): inside a top-level class rule, at any depth, a rule whose prelude only joins class characters to `&` (`&__switch`, `&--featured`) is the rule of the joined class; every other prelude keeps its meaning, and a join inside a width's or a state's block stays nested. A class's rules are read together in file order: a value is its last declaration and is changed there; a new declaration or block goes into the last rule (for the base, the first rule whose width block sets the property, if any), above the body's first context block or joined rule. `listRules` lists each top-level rule as written; `readRule` merges a class's rules.
- New classes (ADR 0067, `domain/style/class-name.ts`) are `<block>__<part>`: the block from the one class of the JSX root (up to its first `__` or `--`), else the file name. A new rule of a class that starts with a top-level class plus `__` or `--` is written nested as `&__part` at the end of that rule; `dropRule` takes it away byte for byte. `min-width` and `min-height` are dimensions like `width` and `height`.
- List ops (ADR 0055) rewrite only the touched array items' text and keep commas, line breaks and indentation; an array that is not an inline literal or a same-file `const` is refused (`list-not-literal`). `findList`, `listInfo` and `itemTexts` keep their meaning: an element behind a condition or in a nested `.map` is `computed` there.
- Item ops by path (ADR 0065): `moveItem`, `duplicateItem` and `removeItem` are for the root its innermost list's callback returns; any other element is refused (`not-list-item`). With a `path` they act on the array that copy's innermost list maps over (`domain/list/nest.ts`, `innerArrayAt`), also a field of an outer item. A `moveItem` with a `toPath` whose outer places differ takes the item's text out of its array and puts it into the same list's array of the other parent in one change of the text (`moveAcrossText`), so one inverse undoes both. The inspect, asked with a `path`, reads the list for that copy (`domain/list/view.ts`).
- Text sources (ADR 0060): a `setItemText` with a `path` (the copy's place in each list around the element, outer first) rewrites, in its own quotes, the one string literal of the file that renders its `before` (`domain/list/source.ts`): an operand of the element's only `{…}` (`domain/expr/leaves.ts`: the branches of `?:`, both sides of `||` and `??`, the right side of `&&`), or the item's field it reads, also in an inner list over a field of an outer item (`domain/list/nest.ts`). None is `computed`, several `ambiguous`, and an operand whose value it cannot read (a call, a prop, a component) refuses too, as it may be the text; never a guess. `textSourceOf` (`app/inspect.ts`) answers the same rule without writing. An expression `className` whose every value starts with one class has that class as its style class (`domain/expr/class-start.ts`).
- Stage 4d (ADR 0056): `app/locks/` refuses an op that changes a locked element (`locked`); `app/suggest/` finds the kit component a plain element looks like (`inspect.ts` sets `suggest`; `source` is empty when no safe replacement exists); `app/history/` and `domain/identity/` follow an element back through versions. A duplicated list item with a literal `key` gets a unique one in the copy (`domain/list/keys.ts`); a key read from another field is left to the person. Adding a utility to an empty `className=""` writes it inside the quotes.
- Never write `position`, an offset, a transform or an id attribute into a draft.
