# src/checks

Checks the latest version of a draft and writes `build/json/checks.json`. `kitvas check` builds first, so a check always sees the current sources.

- A finding has a rule id `<check>/<name>`, a severity (`fix`: wrong; `review`: a person decides), a place in the draft version, an element id when there is one, and a message with a hint. The shape is `domain/findings/finding.ts`; change it there.
- Rules put their message as a key (`checkRule.<name>`, `checkHint.<name>` in `locales/en.json`); the use case translates. Text from esbuild, Sass and tsc goes through `checkRule.tool` unchanged.
- The `types` check writes `build/json/tsconfig.json`: paths to the kit's entry and to `@types/react` (the project's own when it has them), the project's import patterns and the type files its own check reads without an import (`readProjectResolve`, ADR 0092: as `paths`, `files` and `include`), and `client/types/assets.d.ts` for style and asset imports. Then it runs tsc from the `typescript` package as a child process. Only errors under `src/` are `fix`. For a project kit, errors outside `src/` are dropped because `kit verify` checks them.
- The `ds` check reads sources, never the page: imports (`domain/code/code.ts`), plain controls from `ids.json`, and style sheets (`domain/code/styles.ts`). For a Tailwind kit, also the class strings of the TSX (`domain/code/tailwind.ts`) against `build/json/tailwind.json`. A size is compared only with tokens of its kind (spacing, radius, font size); a kit without such tokens gets no size findings.
- A new rule (the book, ADR 0043): an entry in `domain/guidelines/`, a rule object `{ id, run }` in `domain/rules/`, four message keys (`checkRule`, `checkHint`, `guideline.<key>.rule` and `.why`), and a test built with the facts builders in `test/checks/rules/facts.ts`. Rules import no Node module. No number outside the book: thresholds come from the entry.
- The book (`domain/guidelines/`): `basis` is `source` only with a fetched https source, else `heuristic`. `fix` only for a sourced threshold or plainly broken output; the rest is `review`. A finding caused by a kit component's own markup is `review` with the `kitInternal` hint. `kitvas guidelines [<id>]` prints the book.
- Page facts (`domain/page/facts.ts`) are measured in the page, once per visit, then the passes run in this order: `reflow`, `focus`, `states`, `deep`, `spacing`, `press` (ADRs 0044 and 0085). `deep` precedes `spacing` because the override changes every text's layout; `press` is last and only at 1280 px, in no option visit, because using the controls changes the page for good. `states` and `press` fill `facts.states` and `facts.press`; a pass that throws leaves its list empty. Every check also makes a measured visit at 768 px, and `--deep` adds the extra passes and measured visits at 1024, 1440, 1920 and 2560 px; at these widths only the rules in `DEEP_WIDTH_RULE_IDS` run (ADR 0073, 0074).
- The browser checks (`app/browser-checks.ts`) open `build/html/index.html` from disk in every state at 390 and 1280 px (and measured at 768), one browser per run and one context per visit, and write `build/shots/<state>-<width>.png`. Without a browser they are skipped with a note; nothing is downloaded unless the person runs `kitvas browser install`.
- Shared values (ADR 0086): `ux/shared-unused` is a static rule (`domain/shared-values/`), called in `app/run-checks.ts` beside `options/unknown`; it reads the section files for `setShared({ <id>` and `shared.<id>`, never `index.tsx` or `shared.ts`.
- Options (ADR 0082): after the states, `browserChecks` visits each option's other values one at a time (`Visit.options`, the values off their defaults) in the baseline state at the two main widths, so a version adds two visits a value, never the product. Those visits take no part in the state rules; their findings carry `options` (`RawFinding.options`, merged like states, and `[]` once the default combination saw it too). Shots `<state>-<width>.<id>-<value>.png` go to `optionShots`, not to `shots`; `app/option-effect.ts` compares their bytes with the default's for `options/no-effect`, and `options/unknown` reads the SCSS (`domain/options/`).
- What a visit reports is turned into findings by pure rules: `domain/page/page.ts` (axe, blank states, errors, console, failed requests) and `domain/page/usage.ts` (kit components held to the catalog). The JSX runtime in `client/jsx/` records the usage; the bundle's entry puts the kit on `globalThis.__KITVAS_KIT__` so it knows the names.
- Code passed to `page.evaluate` runs in the browser: it uses nothing from its module.
- `kit verify` is `app/verify-kit.ts` with one file per step in `app/verify/` (`schema`, `imports`, `types`, `render`, `tokens`). A step returns issues with a place in kit.json and a message key; nothing is translated here. Only a failed `schema` skips the rest. The answer is also written to `verify.json` in the catalog folder (`domain/kit/kit-verify.ts`).
- `imports` bundles a probe that imports the entry and then every component from its own module: esbuild takes a missing name in a TypeScript re-export for a type and stays silent, so the generated entry alone proves nothing.
- `types` writes `build/json/kit-types.tsx` (`domain/kit/kit-types.ts`): each use on its own lines, with a map from line to claim. Examples that do not parse stay out of it, because tsc reports no type error while a file has a syntax error. Messages in the design system's own files are not reported; only the generated file and the kit's entry are.
- `render` and `tokens` share one catalog build and one browser session, and use `BrowserSession.inspect`. Colours are compared as the browser paints them (`domain/kit/token-compare.ts`), so the kit's hex can be held against oklch or hsl. A written kit has no variables of a design system: its `tokens` (`writtenTokensStep`) holds each `var(--kit-…)` of its component files to the kit's tokens (`unknownTokenVars`), with no browser.
- `look` (`app/verify/look.ts`) is the sixth step and runs only for written kits. It captures each example with a `reference` and scores it with the pure `lookScore` (`domain/kit/look-score.ts`): `size`, `colour`, `structure`, the lowest wins, line `LOOK_LINE`. It is advice: a failed `look` makes `valid` false but never blocks drafts. A component with no referenced example is one `lookNoReference`, not a failure; a `code` kit gets none, because `compared` says how each component was held.
- `original` (`app/verify/original.ts`, ADR 0093) is the seventh step and runs only for a `code` kit with a built catalog and a session that has `measure`. For each example with an `original` it compiles the page's styles (`ProjectStyles`, a dependency of `verifyKit`), writes `originals/<key>.html` into the catalog folder from `domain/kit/original-page.ts`, measures both pages (at 390 too when the styles have a width breakpoint) and compares them frame by frame in `domain/kit/original-compare.ts`: boxes to half a pixel, every other number to 0.01, `tag`, `ks`, `ownKs` and `svg` never. The pairing stops at the first node whose kind or parent differs (one `structure` finding). The picture is the net for what the walk does not read (`ORIGINAL_LINE`). A style that cannot be compiled or a page that cannot read a style leaves the component `read` (advice, no numbers); a declaration every browser drops, the app's too (`cursor: hand`: no build mark in its value), does not (`needsBuild`). A finding fails the step but never blocks a draft; the step never throws. `domain/kit/compared.ts` gives each component its level (`app`, `code`, `read`) for `verify.json` version 3.
- `kit previews` is `app/kit-previews.ts` (ADR 0075): the catalog build, then `BrowserSession.shoot` (`adapters/images/playwright-shoot.ts`) writes one PNG per component's first shown example and one of the icon sheet into `previews/<set>/` of the catalog folder, and `previews/previews.json` (`domain/kit/previews.ts`) last, keyed by the catalog stamp's key and `PREVIEWS_FORMAT`. Bump the format when a shot changes (viewport, scale, box). `readPreviews` only reads; the studio calls it.
- `scanKit` and `cropKit` (`app/scan-kit.ts`, `app/crop-kit.ts`) use `BrowserSession.scan` and `crop`. The scan policy (`domain/scan/addresses.ts`) is the only guard against private addresses: every request and redirect goes through it. Facts hold page text only as `{ "pageText": … }` and are checked by `ScanFactsSchema` before they are written (`domain/scan/scan-facts.ts`). Limits live in that file; change them there. Scan, crop and look code that runs in the page uses nothing from its module.
- The studio's shared browser comes in through `PlaywrightOptions.shared`, which `src/main.ts` fills from `SHARED_BROWSER_ENV`. The endpoint is a secret: never log it, print it or put it in a finding.
- Rework (ADR 0045, 0047): `before/` sits next to the version folders (`domain/rework/before.ts`). On a `rework` draft the checks add `ux/protected` and `ux/before-problems` (`domain/rework/rework.ts`) and the `rework` block `{fixed, left}` in `checks.json`. The original's problems are kept uncapped; `MAX_FINDINGS_PER_RULE` limits reports only.
- Waivers (ADR 0055): after the findings are merged and sorted, `runChecks` splits off those a waiver accepts (`domain/findings/waived.ts`, waivers from `waiversFor` in the drafts module, an element's waiver kept only while the build has it). They go to `waived` in `checks.json` with their reason, count in `summary.waived`, and never in `findings`, `fix` or `review`. A finding with no element is waived only by a waiver with none.
- Locks (ADR 0056): `edit/locked-changed` (fix) is raised from `domain/locks/` when a locked element's source, whitespace collapsed, differs from the text kept at lock time; moving an ancestor (new indentation) is no change. The checks only report; the studio offers Restore, and nothing is reverted.
- The `craft` pass (`domain/page/craft-facts.ts`, `domain/rules/craft.ts`) measures the board's sketches against the kit's icons (`data-craft-sketch`, `data-kit-icon`, `data-craft-tone`); its rule ids are `ui/icon-*` and `ui/logo-*`.
