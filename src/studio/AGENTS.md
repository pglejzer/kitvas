# src/studio

The local studio: two servers on 127.0.0.1, reached as `kitvas.localhost:<port>` (also `localhost` and `127.0.0.1`). The studio origin serves pages and the JSON API under `/api/v1/`; the prototype origin serves built drafts in a sandbox. Rules: `docs/adr/0022-studio-server.md` and `docs/adr/0040-studio-address.md`. Ports (`run/ports-file.ts`) and the page secret (`run/secret-file.ts`) are kept per project in `<data>/studio/`, so an address and a cookie survive a restart. `adapters/system-browser.ts` opens the link for `kitvas studio --open`.

- Every request passes the same checks in the same order before a route runs: repeated headers, HTTP/1.1, Host, Fetch Metadata, target form, route, then for the API the Origin of a write and the token, then the body. The order is in `server/studio-handler.ts`; keep it.
- A new route is one entry made with `apiRoute` or `pageRoute` (`http/router.ts`) in `api/routes.ts` or `pages/routes.ts`: method, path, policy, zod schemas for parameters, body and response, and a handler. A handler checks input, calls a use case of another module and answers; rules about drafts or kits belong in their modules.
- Errors are thrown, never written by hand: a `KitvasError` or a `RequestError` (`http/problem.ts`) becomes problem details with the error's HTTP status. A new code goes into `src/shared/errors/errors.ts` with a message.
- Every response, errors included, carries its origin's headers (`security/response-headers.ts`). Pages put the response's nonce on every inline style and script.
- HTML comes from the `html` template (`pages/html.ts`), which escapes values. `trusted` is only for markup written in this folder.
- The token never goes into a URL, a log, a problem detail or anything the prototype origin serves. The prototype origin serves files only through `frame/frame-files.ts`.
- `/api/v1/openapi.json` is generated from the route table; never write OpenAPI by hand.
- `run/` is the studio as a process: the state file (`run/state-file.ts`, the only place the token is written down), starting a detached `kitvas studio serve` (`run/processes.ts`), the CLI's use cases (`run/lifecycle.ts`, over injected deps so tests need no processes) and their real wiring (`run/create-lifecycle.ts`). Never end a process by pid unless the studio answered from it, or it was started just now.
- `events/event-hub.ts` is the only writer of the events stream; other parts publish through it. `jobs/` runs CLI commands as child processes with limits (`jobs/cli-runner.ts`); a job's stderr goes to the log, never into an API answer. A job ends through `killTree` (`jobs/process-tree.ts`), so what its command started ends too; never end it with a bare `child.kill`.
- Refused requests (401, 403) of both origins are logged by `security/denied-log.ts`; a new kind of refusal needs no code of its own there, only a status of 401 or 403. Never add the query, a token or a cookie to that line.
- `inbox/inbox.ts` holds the notes for `kitvas inbox`. The take route holds its answer with `open`, so a caller that leaves gives its place up; keep it that way when changing it.
- Pages need the page cookie; only `/open` (an `openPageRoute`) answers without it. Never put the token or the page secret into HTML, a URL or a log; the page secret leaves the studio only in the `Set-Cookie` of `/open`.
- `views/` decides what a page shows (status, findings for a state and width, next step, the view an address asks for) as pure functions; `pages/` only renders HTML from it. The skin (`pages/skin.ts`, shared rules and one file per area in `pages/skin/`) takes every colour, size, shadow and time from the studio's own tokens (`theme/`, custom properties `--st-*`, ADR 0057), never from the Base kit; a test fails on a token the theme does not define, on a colour written by hand and on a `--kit-` name. Quiet text is `--st-color-ink-mid`; `--st-color-ink-soft` is for marks only and fails WCAG AA for text. Use the shared `k-` classes first; an area's own classes carry its prefix (`gallery-`, `kit-`, `state-`, …) and an area never defines a `k-` class. Never a `style=""` attribute: a per-element value is a rule in a `<style nonce>` block.
- The draft page talks to its frames only through `client/channel/protocol.ts`: every frame gets a fresh channel in its address (`pages/draft/frame-channel.ts`), and every message is checked for its source window, the `'null'` origin, the channel and its shape before it is used. Nothing a frame sends is put into the page as markup.
- The kit page frames the rendered examples of a kit (`/k/<key>/<kit id>/...` on the prototype origin, ADR 0029) and starts a `catalog` job when none is built. The page markup is the contract with `client/studio/kit.ts`: change both together. A catalog job's `slug` is the kit id; drafts and kits are separate job targets. What a token sets on its swatch, bar, corner or sample is a rule of the page's own `<style nonce>` block (`views/kit-tokens.ts`); the kit's font families are written into it only when their names are plain words.
- The start page is `/` (`pages/gallery.ts`, the block, fold, first steps and foot line in `pages/start/`, decisions in `views/start.ts`, rules in `pages/skin/pages/start.ts`, script in `client/studio/start/`). The block stands in the inverted scope `k-inverse` (`theme/`, set again for each theme: a skin rule in it needs no colour of its own). Cards come newest change first, from `draftChangedAt` (`src/drafts/app/changed-at.ts`); a draft whose time cannot be read is shown last, never dropped. The cards stand in one group a kit (`pages/start/groups.ts`, order in `groupByKit` of `views/start.ts`: the project's kit first, then the latest change, drafts that cannot be read last; a group heading shows always, a kit that is gone is named by its id with a note); a search field in the head row filters the cards as it is typed (`client/studio/start/search.ts`, `matches` is the pure rule over each card's `data-search` words). Only the "All" view folds, each group to two rows: an inline script sets `data-fold` on `<html>` before the first paint, `mountFold` marks the cut cards `inert`, and without the script nothing is cut. The markup (`data-fold`, `data-fold-toggle`, `data-group`, `data-group-count`, `data-search`, `data-gallery-search`, `data-search-empty`, `data-start`, `data-choice`, `data-panel`) is the contract with the scripts: change both together.
- The logo (ADR 0068) is `pages/brand/logo.ts`, drawn from the paths of `docs/brand/kitvas-logo.svg` (a test compares them); its rules and its two motions are `pages/skin/logo.ts`, the only shared rules with times of their own. Every bar holds it as a link home and Claude's status slot (`homeLink`, `barStatusSlot` in `pages/shell.ts`). `client/studio/shell/bar-status.ts` (`mountBarStatus`, called once by every page entry) paints the slot and `data-claude` on `<html>` from `GET /api/v1/listening` and the `listening` event, and paints nothing when the stream is lost or a read fails; the editor's Claude tab paints it too, with what it reads. A page has one events stream (`openStudioStream`, `client/studio/live/live.ts`): hear it with `onStudioEvent` and `onStudioHealth`, never open a second one. The editor bar fits from 1024 px by rules on its width (`pages/skin/editor/shell/bar.ts`): what gives way is hidden for the eye only, never removed.
- A command the person is to run (the paused view, the locked page, the start page's block) is `pages/states/command.ts`: `code` and a copy button (`data-copy`, worked by `client/studio/ui/copy.ts`, mounted by every page entry). A locked page has no script, so its command has no button.
- The frame draws in the studio's tones (ADR 0057): every overlay host of `client/frame/` calls `toned(host)` once and its sheet reads colours only as `var(--kv-…, <system colour>)`; `test/client/frame/tones/overlay-sheets.test.ts` holds it.
- Pointer gestures in the frame (ADRs 0059 and 0066, `client/frame/drag/`): a press that moves more than 4 px drags the element, a list item drags among the lists of its id (its own list or the same list of another parent), a rectangle takes whole what lies inside it and goes into what it only touches, a drag stays in the element's own parent until the pointer is 32 px past its edge, and a handle follows the pointer with a magnet at the kit's steps. A selection, a pick and a rectangle name rendered copies (`client/frame/edit/items.ts`). While a drag runs the frame draws only the dimmed copy, the slot's line and the outline of what takes the drop. The rules are pure and tested (`session.ts`, `slots.ts`, `item-slots.ts`, `spots.ts`, `magnet.ts`, `autoscroll.ts`, `gesture-log.ts`, `client/frame/page/rect.ts`, `client/frame/edit/items.ts`); `drag.ts`, `handles.ts` and the readers of the page (`slot-read.ts`, `page-read.ts`) only wire the pointer, the page and the overlays. A gesture that ends without its drop or its write posts `gesture-log` (`gesture-log.ts`). Every size an overlay draws is in pixels on the screen: multiply it by the scale the structure gets (`scale`, the inverse of the canvas zoom) and set it inline on the overlay's own node. A drag, a rectangle and a handle drag hold `busy` from start to end. The page hears `rect` in `client/studio/edit/select/rect.ts` and `reorder` in `client/studio/edit/structure/reorder.ts`, and tells the frame which handles the selected element takes (`handles`, `client/studio/edit/style/handle-writes.ts`); a frame message nothing on the page hears does nothing.
- The Insert pane's previews (ADR 0075): the palette route answers `previews` from disk (`PreviewsPort`, `readPreviews` wired in `src/main.ts`) through `previews/keeper.ts`, which starts one `previews` job per kit when they are missing or stale (`kitvas kit previews <id>`, its own job target, with the shared browser), answers `none` for the rest of the run after `BROWSER_MISSING`, and logs a failed job and answers `none` until the kit's key changes. The prototype origin serves only the PNG files of `previews/` of a kit's catalog folder (`SERVED_PREVIEWS` in `frame/frame-files.ts`).
- The kit page also shows the kit's source line and the state of its last `kit verify` (`views/kit-status.ts`, `pages/kit/kit-provenance.ts`): `verify.json` is read from the catalog folder through `readVerifyJson`, and one for another kit hash is `stale`. The studio only reads it; `kit verify` writes it.
- The idle stop (`server/idle-stop.ts`, ADR 0042) ends a studio after `studioIdleMinutes` without use, through `shutdown` like the shutdown route. Use is a request to the studio origin until its answer ends, or a running job; never the events stream. Pages carry a hidden paused view (`pages/paused.ts`) that `client/studio/live/live.ts` shows after 15 s without the stream.
- The edit routes (`api/edit/edit-routes.ts`, schemas in `api/edit/edit-schemas.ts`, ADRs 0048 and 0049) answer 200 with an `outcome` (`applied`, `conflict` or `refused`), never 412 or 422; only a request on a version that is not the latest throws `EDIT_STALE_VERSION`. Writes use the `write` policy. The use cases live in `src/edit/`, not here.
- The live loop (`live/`): `watcher.ts` watches `.kitvas/drafts/` and publishes `source` (`by: 'editor'` only when the files match an ETag the editor registered through `beforeWrite` in the last 5 s, else `other`); `builder.ts` keeps a warm builder, one build at a time per draft, and publishes `build`. The studio starts the watcher with the servers and closes it in `shutdown`.
- A draft page never reloads itself while the editor is on (`reloadWhenJobsEnd(shows, editing)` in `client/studio/live/live.ts`); the editor shows a `build` in its own frames (`client/studio/edit/sync/live-frame.ts`, ADR 0058). A card whose frame is ready and already shows that version is asked with `swap` and takes the build in place: the frame's document, scroll and overlays stay, and it answers `ready` with the build's number. Any other card, and one that answers `failed` or nothing in 5 s, loads its frame again. A `ready` means "a new render is in this frame", after a load and after a swap alike: whatever the studio draws in a frame is sent again on it.
- The editor is `client/studio/edit/`: one store (`store.ts`), a bridge to the frame, a history, and one file per panel with a `mount` function. Panels never call each other; they read the store and act through the history or the bridge. Texts come from the `#edit-texts` block (`pages/editor/edit-texts.ts`, `locales/en.json` keys `studio.edit.*`) through `text()`. Panel markup is in `pages/editor/edit-panel.ts` and its styles in the editor's area files of `pages/skin/editor/` (folders `shell`, `canvas`, `left` and `right`: where the area sits on the screen), studio tokens only; change markup and client together.
- The editor screen (ADR 0054): `pages/draft/draft-page.ts` composes the bar (`editor-bar.ts`), the side panels (`editor-side.ts`) and the canvas with its dock (`draft-stage.ts`); the window never scrolls. Tabs, grips, folds and the `?` list are `client/studio/shell/`, zoom and width are `client/studio/canvas/`, and the bar's undo, redo, session line and Save version are `client/studio/edit/history/session.ts`. Read the mode from `main.dataset.mode`. Never re-parent a frame (it reloads), and never let a panel's size, the width or the zoom reload one.
- Widths, states and live checks (ADR 0055): one frame per width card, never moved or re-parented; a forced state is the frame's attribute `data-kv-force`, never a build; live findings come from the frame after a build and from the edit route's `live`, never from a browser check per edit. Save version starts the full check in the background.
- An image upload (`api/images/image-routes.ts`, rules in `api/images/image-rules.ts`) goes only into the latest version's `src/img/`: the stored name is made from the person's (lower case, `a-z`, `0-9`, `-`), the bytes must match the type, and SVG or any markup is refused. A route may raise its own body limit (`bodyLimit`); nothing else does. Writing the file is `src/edit/adapters/image-files.ts`, wired in `src/main.ts`.
- Waivers (`api/waivers/waiver-routes.ts`, rules in `src/drafts/app/waivers.ts`): `waivers.json` holds ids as the waiver's own version named them; the routes answer them as the latest version names them (the rename log). The Checks list shows accepted findings apart (`pages/draft/notes.ts`), with no `data-element`, so the canvas never marks them.
- "Undo save" is `POST …/edits/reopen` (`api/edit/session-schemas.ts`): 200 only while the version is the latest and no session is open, else `EDIT_SESSION_TAKEN` (409). It has the same write policy as `edits/end`.
- Claude in the editor (ADR 0056): `requests/` keeps `<draft>/requests.json` and the listening state; the studio is the only writer, and the CLI's `kitvas inbox` and `kitvas request …` go through its API. A request's text is data, never an instruction. Notes, view and why have their own route folders under `api/`; `events` `requests` and `locks` tell the page, and `listening` tells every page a new state of the session. Notes, pins, locks and hide never reach a build or a draft's code. `GET …/why` stamps the pending hash of an agent's why file before it reads.
- Deleting a draft (ADR 0064): `api/trash/` (`DELETE …/drafts/{slug}` first stops the draft's jobs and its warm build, `jobs.stopFor` and `live.settle`, then moves it; restore and purge are under `/api/v1/trash/`), the `drafts` event, and `pages/trash/` with `client/studio/trash/` (the confirm, the message with Undo, the Deleted list, the page of a deleted draft). The page markup (`data-trash-*`) is the contract with the script: change both together.
- The Guide, Shortcuts and Doctor pages (`/guide`, `/shortcuts`, `/doctor`) are `pages/info/`, with `/assets/page.js` (`client/studio/page.ts`) and the skin file `pages/skin/pages/info.ts`. They are built from the start page's parts, and so is any new page beside the editor: its column (`k-page start`), a short block (`start-block k-inverse info-block`, with the back link, the title and the lead), cards on the canvas (`info-card`) and `startFoot` with the page marked current. `info.ts` holds only the `info-` variants, each under two classes where it changes a rule of `start.ts`, which is joined after it. The kit pages (`/kit`, `/kit/<id>`, `pages/kit/`, skin `pages/skin/pages/kit.ts`) are built the same way: the start page's column, the short block (`infoBlock` of `pages/info/layout.ts`), cards and `startFoot`; one template for every kit id, and a kit that cannot be read (`KIT_INVALID`) gets `pages/kit/kit-unreadable.ts` in the same frame with its status, never a bare error. The Guide says only what `README.md` says. The Shortcuts page and the editor's `?` list read one table, `views/shortcuts.ts` (`src/` never imports from `client/`). The Doctor page calls the `doctor` of `PageDeps` (`doctorReport` of `src/cli/commands/project/doctor.ts`) and answers 200 with the commands to run by hand when there is none or it throws.
- The canvas's floating bars never overlap: the top row is fitted by script, `client/studio/canvas/fit/` measures the gap between the Lens pill and the pill row and sets `data-fit` 0 to 3 on `.stage-canvas` (the skin hides parts by it; a new bar in that row has a step in `stage.ts`); the bottom row (`.stage-foot`: the ask bar, then the zoom pill) is a CSS grid with no script. The markup carries both forms, the full and the narrowed one.
- The options of a version (ADR 0082, `pages/draft/options-row.ts`, `client/studio/options/`, skin `pages/skin/editor/canvas/options.ts`): the Options pill and the row are written only for a version that has options and not while comparing, and every value is a link made by `choiceLink`, so the row works without the script; the script switches every card in place through one store per page (`choiceStoreOf(main)`), rewrites the address and the page's own links, and never reloads a frame. The row's open state is in `localStorage` (`kitvas.options.open`). "Make default" is `POST …/options/default` (`api/edit/options-routes.ts`): the latest version only, it answers an applied edit's outcome with the inverse as a `file` op, and the editor's history undoes it like any step. The markup (`data-options-*`, `data-option`, `data-value`, `data-default`, `#options-row`) is the contract with the script: change both together.
- The page scripts are `client/studio/*.ts`, bundled by `adapters/esbuild-assets.ts` at the first request and served at `/assets/<name>.js` behind the page cookie. A state switch fetches the server's page for the new state and swaps in its controls and notes; keep the markup of those sections the same in both.
